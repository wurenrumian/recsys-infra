## 一句话

嵌入表不再全切到所有 GPU，而是分组复制 + 组内切分，配上改过的 AdaGrad 保住效果。

## 背景与问题

工业 DLRM 的嵌入表已经是 TB 级：论文引用的外部大模型（ExFM）有 4000+ 张表、约 2TB、最大 3.2 万亿参数、98% 以上参数在嵌入表里（**事实**：2.1 节）。这种规模只能上模型并行。

传统做法是**全量模型并行（full model parallelism）**：把整个嵌入表切分到所有 GPU 上。GPU 数量一多，三个问题同时恶化（**事实**：引言明确列为 (1)(2)(3)）：

1. **负载不均与长尾拖慢（imbalance & straggler）**。表大小本身就倾斜，表数又多，很难在几千张卡上切得均衡。慢卡拖全局。
2. **all-to-all 查询通信爆炸**。每张卡要为自己 batch 里的 ID 去别处取向量，全量切分意味着 all-to-all 的规模随卡数增长。
3. **嵌入激活内存线性膨胀**。每张卡要存"全局 batch 在自己这张卡上命中的"查询激活，固定 per-GPU batch 时，这部分内存随卡数线性增长。

论文给了定量曲线（**事实**，Figure 2 描述）：卡数往上走时，嵌入计算延迟从 100ms 涨到 200ms（还算温和），但 all-to-all 延迟涨到 **超过 600ms**；同时嵌入查询内存从 256 卡时的不到 4GB 涨到更大规模时的 **接近 15GB**。

作者对文献的判断很明确：现有工作（含 DLRM-v2 那一代的通信/内存优化）**只覆盖到较小的 GPU 规模，解决不了"数千卡"这一档的问题**（**事实**：2.2 节末）。

## 核心做法

### 一、并行结构：MP 外套一层 DP

设总卡数 N，分成 G 个并行组，每组 N/G 张卡。**每个组持有一份完整的嵌入表副本，副本内部再按模型并行切分到组内各卡**。于是系统里有 G 份副本：副本内是 MP，副本间是 DP。

```
                    ┌──────── 组 0（N/G 卡）────────┐
   全局 batch ──┬──→│ 嵌入表副本 0，组内 MP 切分     │──→ 组级梯度
                │   └───────────────────────────────┘
                │   ┌──────── 组 1 ─────────────────┐
                ├──→│ 嵌入表副本 1                   │──→ 组级梯度
                │   └───────────────────────────────┘
                │              … 共 G 组 …
                │   ┌──────── 组 G-1 ───────────────┐
                └──→│ 嵌入表副本 G-1                 │──→ 组级梯度
                    └───────────────────────────────┘
                                    │
                    每步末尾：跨组 all-reduce 同步「表权重 + 优化器状态」
```

三个问题各自被削掉一块：

| 问题 | 机制 | 换来什么 |
|---|---|---|
| 负载不均 | 副本只切到 N/G 张卡，切分粒度小、基数小，容易均衡 | straggler 减少 |
| all-to-all 通信 | 组内 all-to-all 只在自己组内做，参与方少了 G 倍 | 通信量按 1/G 下降 |
| 激活内存 | 每组只看 1/G 的全局 batch | 查询激活内存按 1/G 下降 |

**关键细节**：因为嵌入表的反向与优化是融合的（backward 完立刻 update，不留梯度），所以跨组同步的不是**梯度**而是**表权重 + 优化器二阶矩**（**事实**：3.1 节明确说明 "rather than synchronizing gradients as in common distributed data parallelism, our 2D sparse parallelism approach synchronizes table weights and optimizer states"）。这一点是后面算法问题的根源。

### 二、算法问题：AdaGrad 的有效学习率被悄悄压小

直接套用 row-wise sparse AdaGrad 会掉效果。作者的 Proposition 1 给出解释（前提：各组梯度 i.i.d.）：

- (i) 各组本地更新后的二阶矩**期望相同**；
- (ii) 2D 并行下的二阶矩**期望增量比非 2D 时更大**。

二阶矩更大 ⇒ 有效学习率 lr/√(v+ε) 更小 ⇒ 模型训练不足 ⇒ 效果掉。且**组数越多，掉得越狠**——这跟实验完全对得上。

**修法：moment-scaled row-wise AdaGrad**。在算有效学习率时把二阶矩除以一个常数因子 λ：

```
原式：  lr_eff = lr / sqrt(v + ε)
改后：  lr_eff = lr / sqrt(v/λ + ε)
```

Scaling Rule 1 给出 λ 的取值范围，并指出"梯度信噪比高时偏好更大的 λ"。**实践建议（论文明说）：λ 取组数 G**，省掉调参。

这个改动很轻——一个常数乘除，不改通信、不改内存，但把效果差距抹平了。作者还说可以推广到 RMSProp / Adam 这类同样用二阶矩调学习率的优化器（**事实**）。

### 三、两个必须承认的代价

论文第 5 节专门讲，做法很坦率：

1. **表复制的内存开销**：每组一份副本，额外内存 ≈ (G-1)/N × 表总大小。**与组数成正比、与总卡数成反比**——所以卡多、组少时基本可忽略。缓解手段是压表本身（FP8、unified embedding、tensor-train）。
2. **副本同步延迟**：跨组 ring all-reduce 的每 rank 延迟 ≈ 与复制内存量 / 带宽成正比。缓解手段三招：减少组数、**把组限制在同一台机器内**（8 卡同 host 时同步只在 host 内，实测比跨 host 快 **7×**）、降低同步频率做 local SGD 式的本地更新。

## 为什么值得读

在 Track A 里，A-03 是**通信与切分维度**上的核心一篇。它和 A-04（Persia）、A-06（Neo/4D 并行）构成"切分策略"的三条不同路线：

- **A-06（Neo，Meta）用 4D 并行**：table-wise / row-wise / column-wise / data-parallel 四种切法**按表**选，小表直接复制（DP），大表才切。也就是说 Neo 已经承认"小表该复制"。
- **A-03（本篇）把这个想法推到全局结构**：不是逐表选策略，而是**整个嵌入表在组的粒度上复制**，把 DP 提升为并行拓扑的第二维。可以直接看作 A-06 思路的"整体化 + 千卡化"。
- **A-04（Persia）走的是异构路线**：嵌入放 CPU PS，稠密网络放 GPU AllReduce，靠算法层的异步/同步混合补效率。A-03 全程在 GPU 上，不引入 CPU 层，因此问题纯粹是"卡多了怎么切"。
- 与 **A-15（FusedRec）互补**：FusedRec 优化的正是 A-03 里那条"组内 all-to-all"的传输效率（去重后消息太小导致带宽浪费，改成融合发送）。A-03 降低 all-to-all 的**规模**，FusedRec 提升 all-to-all 的**效率**，两者可以叠。
- 与 **A-14（Dual-Level Lossy Compression）也互补**：那篇压的是 all-to-all 的**字节数**，A-03 压的是**参与方数量**。同样可以叠。

它还是本 track 里**唯一把"改算法以适配改系统"讲透**的一篇：不是"系统改了，效果掉了，就这样吧"，而是先证明为什么会掉（Proposition 1），再给一个一行的修法（λ=G）。这个"系统改动 → 统计后果 → 算法补偿"的闭环，是这条线上最值得学的部分。

## 局限

- **前提假设偏强**：Proposition 1 假设各组梯度 i.i.d.。真实训练里各组看的是不同数据分片，梯度不是 i.i.d.，尤其入口处冷启动阶段。假设破了，"λ 取组数"这个经验法则还能不能直接用，论文没说（**推断**）。
- **只对嵌入层生效**。稠密网络部分仍是标准 DP，论文通篇不讨论稠密侧的扩展。当模型从"嵌入主导"转向"稠密主导"（LLM 化推荐），这套方法的收益面会缩小（**推断**）。
- **组约束在同 host 内的建议限制了拓扑**。第 5 节说组限制在单机 8 卡能拿 7× 同步收益，但这要求每台机器都是 8 卡同构节点；异构集群或 NVLink 拓扑不同的机器上，最优组数要重算（**推断**）。
- **最优组数强依赖模型**。CTR 模型和 ExFM 都是 4 组最优，但 8 组就退化——说明 G 是个需要针对模型/集群调的超参，而论文只给了"λ=G"这一条规则，没给"G 怎么选"的规则（**推断**）。
- **效果指标只有 NE**。没有线上 A/B，没有多任务/排序场景的验证。"效果持平"的结论建立在 normalized entropy 上（**事实**：4.1 节只用 NE）。
- 是**预印本，未见正式发表**（**事实**：Zotero 条目类型为 preprint，只有 arXiv 号）。审稿意见可能揭示的问题无从得知。

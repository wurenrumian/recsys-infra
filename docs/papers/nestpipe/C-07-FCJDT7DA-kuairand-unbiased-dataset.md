## 一句话

快手把随机视频塞进真实推荐流两周，攒出带 12 种反馈的无偏序列数据集。

## 背景与问题

推荐系统离线评测有个根子上的问题：**日志数据是有偏的**（**事实**，§1）。用户在日志里"没有点击"某物品，可能是①不喜欢，也可能是②**根本没被曝光过**——这两种情况在日志里长得一模一样，而后者占了绝大多数。这叫曝光偏差（exposure bias），数据是 MNAR（missing-not-at-random）。后果很严重：基于这种数据训出来的模型会系统性高估热门物品、低估冷门物品，且**无法回答"模型在大量缺失数据上表现如何"**这个核心问题（**事实**）。

现有解法各有硬伤（**事实**，§2.1）：传统指标（Precision/Recall/NDCG）回答不了缺失数据上的表现；off-policy evaluation / 反事实推断高方差且额外引入误差；用户模拟同理；**收无偏数据（MAR）** 要真去收集、成本高。

而已有 MAR 数据集都不够用（**事实**，§2.2）：

| 数据集 | 规模 | 缺什么 |
|---|---|---|
| Yahoo!R3 | 15,400 用户 × 1,000 物品；5,400 用户评 10 个随机物品 | **没有时间戳、没有特征** |
| Yahoo!R6 | 数百万次曝光 | **所有 user ID 被移除** → 做不了协同过滤 |
| Coat | 290 用户 × 300 物品（16 个随机） | 规模太小、**无时间戳** |
| Open Bandit | 约 26M 交互、80 物品 | **无 user ID** → 做不了序列推荐 |

四份数据**没有一份同时具备**：足够大 + 有 user ID + 有时间戳 + 有用户/物品特征。而这四样恰好是"序列推荐 + 去偏研究"的最小需求集。

## 核心做法

### 1. 干预方式：随机替换，不是随机插入

这是全篇最关键的实验设计（**事实**，§3）：用户请求一次推荐列表，以固定概率决定是否干预（概率值未公开，商业敏感）；若干预，则从列表里随机选一个位置，用"从 7,583 个视频里均匀采样"的视频替换它。

三个设计要点：

| 决策 | 选择 | 为什么 |
|---|---|---|
| 随机物品池 | **7,583** 个视频（先采样再过滤广告等 spam） | 池子固定 → 可以精确算采样概率 → 才能做无偏估计 |
| 替换而非插入 | 替换列表中的一项 | 保持列表长度不变，不打乱用户的浏览习惯（减小干预痕迹） |
| 概率值隐藏 | 不公开 | "avoid leaking out the key parameters of the online recommendation strategy"（原文明说） |

**最后一条是个重要缺陷**，见"局限"。

用户筛选（**事实**）：随机抽 >200,000 真实用户并剔除机器人；保留"至少被曝光 10 个随机视频"的 → **27,285** 人；全部 7,583 个物品**至少被插入过一次**。

时间窗（**事实**）：干预期 2022-04-22 至 2022-05-08（**两周**）；历史行为回捞 2022-04-08 至 2022-04-21（**另两周**，**不带干预**、纯自然推荐）；合计一个月 **32,038,725** 个物品、**322,278,385** 次正常推荐。

### 2. 反馈信号：12 种

这是 KuaiRand 相对所有前作的差异化（**事实**，摘要 + §3）：记录 **12 类**用户反馈，包括点击、收藏、观看时长等（原文举例 "click, adding to favorites, and view time"）。意义：多任务学习、多目标排序、以及"什么是真正的正反馈"这类研究都需要多种信号；单一"点击"标签会让研究退化成二分类（**推断**）。

### 3. 三个发布版本

（**事实**，摘要 + §3 末尾 + 附录）

| 版本 | 定位 |
|---|---|
| **KuaiRand-27K** | 全量：27,285 用户 |
| **KuaiRand-1K** | 1,000 用户子集（更小、更快跑） |
| **KuaiRand-Pure** | "纯"版本（推测是只保留随机曝光部分 / 去掉干扰逻辑，**待核实**：正文附录未取到该版本的完整定义） |

### 4. 支持的四种研究方向

论文自己列的（**事实**，摘要 + §1）：
1. **大规模去偏**（主要卖点）：有 MAR 数据，能做无偏离线评估；
2. **交互式推荐**：有真实用户 ID + 时间戳，可模拟多轮；
3. **长序列行为建模**：每用户平均**数千次**交互（原文："each user has thousands of historical interactions on average"），且快手是短视频场景，天然长序列；
4. **多任务学习**：12 种反馈信号。

第 3 点与 NestPipe 这条线直接相关——**长序列不是构造出来的，是场景本身产生的**（快手 DAU 3 亿、人均每天 128.1 分钟，**事实**）。

### 5. 15 个场景 / 15 套策略

（**事实**，§3）快手有 15 个推荐场景（不同 UI 位、微信小程序等嵌入位），每个场景有自己的推荐策略。数据集区分了这些场景。

意义：可以做**跨场景迁移**、**多场景联合建模**的研究。这在本 track 里对应 C-03 MTGR 的未来工作（"extend MTGR to multi-scenario modeling"）。

## 为什么值得读

- **它是本 track 唯一的评测基础设施论文**。C-01 到 C-06 全都在"造更强的模型"，但没人回答"你怎么知道它更强"。KuaiRand 给的答案是：因为标签本身是无偏的。这个视角在 NestPipe 这个以"系统"为主的集合里很少见。
- **与本 track 多篇是"评测被引用"关系**（**事实**）：C-04 FuXi-α 明确在 KuaiRand 上做实验（且用了它的序列长 200/800 做效率测试）；C-05 ULTRA-HSTU 用 KuaiRand-256 做短序列泛化验证。**没有 KuaiRand，这两篇的公开数据部分会少一半**。
- **与 C-02 HSTU 的方法论形成互补**。HSTU 的核心论点是"在线 A/B 才是真信号"（它给的是 12.4% 线上提升）；KuaiRand 的论点是"离线评测必须无偏，否则线上会骗你"。两条合起来才是完整的评测闭环。
- **对长序列研究的价值最大**。NestPipe 关心的"用户序列长度爆炸"在这份数据里是**可测量的真实分布**（几千到几万），而不是论文里的假设值。要做长序列系统的模拟实验，这是少数几个能拿到真实长度分布 + 真实反馈的公开数据。
- **12 种反馈**是稀缺资源。多目标排序/多任务学习的研究者常年缺这种数据。

## 局限

1. **干预概率未公开 = 无偏估计不严格可复现**。做 off-policy evaluation 需要知道倾向得分（propensity）。论文隐藏了固定概率，虽然"均匀采样 + 固定概率"形式上仍然可估（概率是常数，可并入归一化因子），但**跨数据集对比时无法还原绝对尺度**（**推断**）。这是最实质的限制。
2. **随机池只有 7,583 个物品**。这与快手真实物品池（数百万/千万级）差 2–3 个数量级。所以"随机曝光部分"对**大规模**物品空间的研究支撑有限——它验证的是"在 7.5k 池子上的无偏性"（**推断**）。
3. **只有 27,285 用户**。相比快手 3 亿 DAU，这是万分之零点九。虽然对学术研究足够，但做"用户长尾"或"冷启动"研究时样本会不够（**推断**）。
4. **两周太短**。序列推荐里"长期兴趣漂移"通常要看数月；两周窗口捕捉不到（**推断**）。
5. **场景分布不可控**。15 个场景的流量占比未披露，重采样做跨场景研究时要自己处理（**待核实**）。
6. **KuaiRand-Pure 的定义在本文件证据下不清楚**（**待核实**，附录未取到）。
7. **作为数据集论文，无方法贡献**。想找系统/模型洞察的读者会失望。

## 是否值得读原文

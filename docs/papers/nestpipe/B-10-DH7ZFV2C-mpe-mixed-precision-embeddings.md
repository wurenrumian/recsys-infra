- 系统名：**MPE**（Mixed-Precision Embeddings）。

## 一句话

按频率分组、用可微分布搜索每组位宽，Criteo 压 200× 不掉精度。

## 背景与问题

嵌入表压缩有两条既有路线，各自都有局限（**事实**，论文 §1.2 的梳理）：

**① 按行压缩（row compression）**
- 特征选择：OptFS 等，把不重要特征整行删掉 → 本质是"二值精度"（0 bit 或全精度）；
- 哈希：用哈希函数在低频特征间共享行 → 有碰撞损失。

**② 按列压缩（column compression）**
- 混合维度：CpRec 给不同特征不同维度，AutoEmb 用 RL 搜维度；
- 剪枝：PEP 学阈值裁掉每个嵌入内的冗余参数。

**③ 按精度压缩（quantization）**
这是本文的位置。已有工作的关键缺陷（**事实**，§1.2）：

> "quantization typically applies **uniform precision across all embeddings**, failing to distinguish feature importance."

具体来说：
- **PTQ**（Guan et al. 2019 最早把 PTQ 用在嵌入表）掉精度；
- **LPT**（低精度训练，如 ALPT）在低比特下不可行——ALPT 只在 8 bit 时无损，再低就崩；
- **QAT** 在推荐系统里研究极少，原因是嵌入表的特殊性：**特征重要性差异极大，而 QAT 用统一位宽，等于给不重要特征浪费了比特**。

作者的贡献点很清晰：**把"特征重要性"和"精度"关联起来**（前人是把重要性关联到维度、到是否保留），并且指出特征选择只是"0 bit 或全精度"的二值特例，所以混合精度是**更细粒度**的压缩。

### 两个技术挑战

**挑战一：搜索空间太大**。数百万到上亿个类别特征，"给每个特征单独搜位宽"不可行。

**挑战二：位宽是离散的，梯度下降解不了**。而且比单纯的离散选择更难——量化算子本身不可微（round 操作）。

## 核心做法

### 四步流程

```
① 按频率分组        ② 学分布              ③ 采样位宽        ④ 重训
┌──────────────┐  ┌──────────────────┐  ┌──────────────┐  ┌──────────┐
│特征按频次排序 │─►│每组一个可学习向量 │─►│按概率选最高   │─►│用采样位宽 │
│切成 g 组      │  │γ，softmax 得概率 p│  │且 p > 1/(2m) │  │从头重训   │
│每组搜一个位宽 │  │期望嵌入 = Σpᵢ·Q(bᵢ)│  │的位宽        │  │          │
└──────────────┘  └──────────────────┘  └──────────────┘  └──────────┘
   搜索空间÷(n/g)     端到端可微            收敛到 one-hot     消除训练/推理差异
```

### ① 频率感知分组（Frequency-Aware Grouping）

特征按**频次**排序后切成 `g` 组，每组搜一个位宽。

- 依据：频次是已被多次验证的**重要性代理**（引 Sun 2020、Lai 2023、Zhang 2020、Kang 2020）。
- 收益：搜索空间从 `n` 降到 `g`，即压缩 `n/g` 倍；同时组内特征重要性相近，**共享位宽的冲突最小化**。

这一步的取舍很值：它用"分组内可能存在的次优"换"搜索可行性"。如果频率与重要性不完全单调，组内就会有冲突——论文承认这一点但认为频次代理足够好。

### ② 可学习概率分布（核心算法）

对每组维护一个可学习向量 `γ = {γ₁, ..., γ_m}`（`m` 个候选位宽），概率用 softmax：

```
pᵢ = exp(γᵢ/τ) / Σⱼ exp(γⱼ/τ)
```

`τ` 是**温度**：越小越接近 one-hot。初始时所有 `γᵢ = 0`，即每个候选位宽等概率。

**前向怎么算**：不是"选一个位宽"，而是**对所有候选位宽的量化结果求期望**：

```
ē = Σᵢ pᵢ · Q(e, α, β, bᵢ)
```

`Q` 是基础量化器，用 **LSQ+**（带可学习 step size α 和 offset β 的均匀量化）。

这个"期望"的做法是关键——它把离散的位宽选择变成**连续可微**的问题：梯度可以通过 `p` 传到 `γ`，通过 `Q` 传到 `e`、`α`、`β`。

### ③ 正则项（也是本文的一个巧思）

目标函数：

```
L = L_CE + λ · Σⱼ (1/sʲ) · Σᵢ bᵢ · pᵢʲ
```

其中 `sʲ` 是第 j 组的**特征频次之和**。

读法：这是对"每组期望位宽"的 L1 正则，但**按组的频次和做了归一化**。效果是：
- 高频组的正则系数被 `1/s` 压小 → **不急着压高频特征**；
- 低频组的正则相对更强 → **优先压低频特征**。

这一步用一行数学表达了"重要的别压、不重要的快压"的策略，很优雅。

### ④ 精度采样与重训

**采样规则**（不是取最大概率）：

```
b* = max { bᵢ | pᵢ > 1/(2m) }
```

理由（**事实**，论文原文的解释）：概率最高的位宽未必最合适。一个位宽即使不是 argmax，只要概率超过 `1/(2m)`（均匀分布的 2 倍），它对高精度表示的贡献就不可忽略，这组特征"需要"更高位宽。所以取**满足阈值的最大位宽**——偏保守。

**重训**：直接用采样位宽量化会产生训练/推理不一致（训练时用的是期望值，推理时是单一位宽）。所以要用采样位宽**从头重训**。
- 但不像 LTH 那派"全部重置到初始化"，这里**保留搜索阶段的 `α`、`β` 和特征交互网络**，只把嵌入参数重置为搜索阶段的初始值。等于"用搜索学到的量化超参 + 特征网络"初始化重训。

### 实现细节（容易被忽略但很重要）

- **推理时不涉及混合精度计算**：只按混合精度**存储**，取出来后**反量化**成全精度再送后续网络。因为前向取的嵌入只占总量的很小比例，反量化的存储开销可忽略。
- **PyTorch 不支持 Int-2 / Int-3**：所以把每条嵌入向量**按位拼接**后切成 Int-16 存储，取用时再转回全精度。
- **α 与 β 的共享策略**：不为每个特征维护单独的 α/β（太占内存且没必要）。**每个位宽一个 α，每个嵌入维度一个 β**。这是"混合精度必然需要不同 step size、不同维度的表需要不同 offset"的直接推论。

## 关键数字

| 指标 | 数值 | 证据 |
|---|---|---|
| Criteo 上的压缩比 | 约 **200×**，且不掉精度 | **事实**（摘要 "about 200x compression ... without comprising the prediction accuracy"） |
| 数据集 | Avazu（944 万特征/4043 万样本）、Criteo（3376 万特征/4584 万样本）、KDD12（5469 万特征/1.49 亿样本） | **事实**（Table 2） |
| 评测模型 | DNN、DCN、DeepFM、IPNN | **事实** |
| 基础量化器 | LSQ+ | **事实** |

压缩比（**事实**，Table 3 的 `Ratio↓` 列，以 DNN 为例）：

| 方法 | Avazu | Criteo | KDD12 |
|---|---|---|---|
| QR-Trick | 0.5000 | 0.5000 | 0.5000 |
| PEP | 0.9945 | 0.0340 | 0.9947 |
| OptFS | 0.9863 | 0.0187 | 0.9839 |
| ALPT | 0.2500 | 0.2500 | 0.2500 |
| LSQ+ | 0.1875 | 0.1875 | 0.1875 |
| **MPE** | **0.0573** | **0.0055** | **0.0409** |

（Ratio 越低压缩越狠。Criteo 上 0.0055 ≈ 1/182，与摘要的 200× 一致。）

AUC 对比（**事实**，DNN 骨干）：

| 方法 | Avazu | Criteo | KDD12 |
|---|---|---|---|
| Backbone（不压缩） | 0.7955 | 0.8106 | 0.8219 |
| LSQ+ | 0.7954 | 0.8104 | 0.8220 |
| **MPE** | 0.7959 | 0.8104 | 0.8218 |

读法：MPE 的 AUC 与不压缩的骨干**在同一水平线**（差异在 ±1e-4 量级，接近噪声），而压缩比高一个数量级以上。**这是"无损压缩"的实证。**

## 为什么值得读

MPE 在 Track B 的压缩派里站的是"**按精度分配**"这一格，与其他两篇构成完整的三分法：

| 维度 | 代表 | 分配什么 | 粒度 |
|---|---|---|---|
| **行** | B-12 AdaEmbed、B-03 CAFE+ | 保留 / 共享哪些行 | 离散、行级 |
| **维度（列）** | CpRec、AutoEmb（track 外） | 每行多少维 | 离散、行级 |
| **精度（比特）** | **本篇 MPE** | 每行多少 bit | 连续松弛、组级 |

三者**正交可叠**：AdaEmbed 决定留下哪些行，MPE 决定留下的每行用几 bit，CAFE+ 决定哪些行独享。论文自己点出了这个关系："feature selection can be viewed as a binary case of mixed-precision embeddings"。**这是本 track 里把压缩问题分解得最清楚的一篇。**

具体到邻近关系的判断：

- **vs B-03（CAFE+）**：两者都用"重要性"分配资源，但 CAFE+ 用**频次直接决定结构**（独占还是共享），MPE 用**频次做分组先验 + 可微搜索决定位宽**。MPE 的分配是学出来的，CAFE+ 的分配是规则式的。**MPE 更"自适应"，CAFE+ 更"低开销"**（不需要搜索与重训）。
- **vs B-11（DQRM）**：DQRM 用**统一 INT4**，且发现量化有**强正则效果**、反而缓解了 DLRM 的多 epoch 过拟合。MPE 用**混合位宽**，追求的是"在不掉精度的前提下最大化压缩"。两者对"量化的副作用"的态度不同：DQRM 把正则当卖点，MPE 只关注精度不掉。**这两篇对着读能看出一件事：统一低精度有正则收益，混合精度没有这个副作用也没有这部分收益。**
- **vs B-16（Pinterest）**：Pinterest 发现**低频行是多 epoch 过拟合的元凶**。而 MPE 的正则项**优先压低频组**。两者指向同一个对象（低频特征），但一个用学习率、一个用位宽。**可以考虑组合：低频行既降位宽又降学习率。**
- **vs B-12（AdaEmbed）**：AdaEmbed 是"减行"，MPE 是"减 bit"。AdaEmbed 报 35–60% 的嵌入体积节省（在精度还涨的前提下），MPE 报 200×。**差距悬殊**，原因是"减 bit"的下限比"减行"低得多——行删了就没了，bit 可以减少到 2 位还在。

## 局限

- **必须重训**。搜索阶段 + 重训阶段 = 至少两倍训练成本。对于每天都要重训的推荐系统，这个开销是真实的（论文没报总训练时长）。
- **频率作为重要性代理有边界**。B-16 的结论隐含着"低频 ≠ 不重要"（低频行导致过拟合，说明它们承载了不可泛化的信息，但也可能是噪声）。如果低频特征里混着高价值稀有特征（如大广告主 ID），压到 2 bit 会系统性损伤。
- **`g` 和 `m` 是超参**。`g`（组数）越大越精细但越难搜；`m`（候选位宽数）影响搜索空间与软化的平滑度。论文有超参分析，但**调参成本**没量化。
- **只在 3 个公开数据集 + 4 个小模型上测**。DNN/DCN/DeepFM/IPNN 都是"嵌入 + 浅层交互"的结构，参数量远小于工业模型。在 10¹¹ 特征、TB 级表的场景下，"按频次分组"的分组数 `g` 会非常难定（每组特征数巨大，组内冲突加剧）。**工业可扩展性待核实。**
- **反量化到全精度的开销被"稀疏"论证带过**。"取出的嵌入只占总量很小比例"这句话在 batch 很大或 pooling factor 很高时（论文自己测的表里 pooling factor 可达 193）就不一定成立。
- **位拼接成 Int-16 是个 workaround**，不是真正的低位存储。如果硬件/框架原生支持 Int-4/Int-2，MPE 的实际内存收益会更大；现在的实现把收益打了折扣（**推断**）。
- **没讨论分布式训练**。混合精度嵌入在分片（all-to-all 通信）时，通信量是按位宽压缩后的吗？论文没提。

## 是否值得读原文

**必读**——如果你在做嵌入量化。理由：§3.3（可学习概率分布 + 期望量化）是**把离散位宽搜索变成可微问题**的干净解法，可以整段搬到别的离散资源分配问题（比如 B-06 的分片、CAFE+ 的阈值选择）。§3.4 的采样规则（取满足阈值的最大位宽而不是 argmax）是一个反直觉但有说服力的细节。如果只想了解结论，记住 **200× 压缩、精度不掉、按频率分组** 即可。

**不建议照抄的地方**：如果你要上工业规模（上亿特征），先评估"按频次分成 g 组"这个做法在组内冲突加剧后是否还成立。

## 一句话

异步流水的 stale 梯度之所以害人，是因为 Hessian 基与坐标基错位；转个基就好。

## 背景与问题

### 异步 PP 的诱惑与代价

同步 PP 的痛点是气泡：每个 stage 必须等所有 stage 的反传完成才能更新权重（**事实**，§1）。异步 PP 让 stage 不必等，硬件利用率大幅上升，**但引入梯度 staleness**——梯度在被算出来和应用之间，模型已经更新了好几轮。

### 一个被忽略的病理：延迟随深度线性增长

这是全篇的核心发现（**事实**，摘要原文）："this delay scales linearly with pipeline depth, fundamentally undermining the very scalability that the method originally intends to provide." 工程上这意味着：**异步 PP 想靠"加更多 stage"来扩规模，但每加一层 stage，staleness 就多一分，最终把扩规模的好处吃回去**。论文实测（**事实**，§1）：固定模型、增加 stage 数 → 收敛速度**慢 5.81 倍**。这个数字很扎眼——不是"略微退化"，是"异步 PP 在深流水线上基本不可用"。

### 更深一层：为什么会这样

作者的归因非常具体（**事实**，§1 + §2）：① LLM 预训练的默认优化器是 **Adam**（逐坐标自适应步长）；② Transformer 的 loss 曲面曲率异质（不同方向曲率差别巨大），所以单一全局步长不行、必须逐坐标自适应——这是 Adam 成为默认选择的原因；③ **但逐坐标自适应性依赖一件事：Hessian 的特征基与"坐标轴"重合**。

第 3 点就是全部论文的关键。用一个二次目标 `min ½ wᵀHw` 说清楚（**事实**，§2.2 + Fig.3）：**情形 A**——H 是对角阵（特征基 == 坐标基，对齐），AdaSGD 沿主特征方向震荡、非主方向缓慢前进，而 Adam 几乎直线走向最优点，自适应真的起作用了；**情形 B**——H 非对角（基错位），Adam 的自适应性失效，轨迹退化成 AdaSGD 那样在主方向上剧烈震荡。

而**震荡正是延迟的放大器**（**事实**）：轨迹平滑时 `u_t ≈ u_{t-τ}`，延迟更新与真实方向仍接近，影响很小；轨迹震荡时 `u_t` 与 `u_{t-τ}` 可能**方向相反**，延迟更新变成"对抗性"的，严重拖慢收敛。

论文用一个"螺旋 loss 曲面"（spiral loss landscape）验证这一点（**事实**，§2.3）：沿训练轨迹随机取点，测"有无延迟时的迭代比 `T_delay / T_no-delay`"，结果**基对齐区域比值最小，基错位区域比值最大**（Fig.4）。

### 形式化：延迟与错位是乘性耦合

论文给的收敛界（异步 Adam，β₁=0，延迟 τ）（**事实**，Theorem 2.3）：

```
E‖∇f(w_t)‖₁ ≲ sqrt( (1 + dτ)·Δ₀·C / T ) + Σσ_i·( (1+dτ)Δ₀C/T )^{1/4} + Σσ_i·(log T / T)^{1/4}
```

关键结构：**`τ` 与 `C` 以乘积形式出现**（**事实**，原文明说 "τ enters the bound multiplicatively with C"）。

- `C = Σ_i C_i` 是坐标级 ℓ∞ 平滑常数；
- 而且 `C` 局部对应 Hessian 的 `(1,1)` 范数 `‖∇²f‖_{1,1} = Σ_{i,j} |(∇²f)_{i,j}|`；
- **固定特征值谱下，这个范数在对角时最小，基错位时增大**（**事实**）。所以 `C` 是"错位程度"的代理指标。

结论：基对齐时 `C` 小 → 延迟项被压制；基错位时 `C` 大 → 延迟项主导界。并且延迟把确定性收敛率从 `O(sqrt(1/T))` 拖到 `O(sqrt(τ/T))`（**事实**，与异步优化文献一致）。

还有一条**实用的推论**（**事实**，Theorem E.6）：分 stage 各自延迟时，有效延迟是 `τ' = sqrt( Σ_i C_i² τ_i² / Σ_i C_i² )`，即"**按曲率加权的延迟**"。由于早期 stage 的 `τ_i` 最大（延迟 = K−k），**早期 stage 主导收敛退化**——这个推论后面直接变成了一个工程优化（stage-aware rotation）。

## 核心做法

### 主算法：在 Hessian 特征基里做 Adam

思路一句话（**事实**，§3.1）：把优化空间旋转，使 Hessian 特征基与坐标基对齐；在这个空间里跑 Adam；再转回来。

```
原始空间                        旋转空间
w̃ = Uᵀ w  ──►  m̃ = EMA(Uᵀ∇f);  ṽ = EMA((Uᵀ∇f)²);  w̃ ← w̃ − η·m̃/(sqrt(ṽ)+ε)
                                 │
w ← w − η · U · EMA(Uᵀ∇f) / sqrt(EMA((Uᵀ∇f)²) + ε)   ◄──┘ 转回原空间
```

U 是旋转矩阵，列是 Hessian 的估计特征向量。当 U 完美对齐特征基时，旋转空间里的 Hessian 特征基**恰好就是标准坐标基** → Adam 的曲率感知自适应性恢复（**事实**）。

### 让它变得可行：两个结构性假设

直接算 `U ∈ R^{mn×mn}` 是不可能的，两个假设把成本压下来（**事实**，§3.1）：**块对角**——Hessian 按权重矩阵分块对角，于是可按矩阵为单位旋转而非整个参数空间（Transformer 上被经验支持，引 Zhang et al. 2024/2025b、Abreu et al. 2026）；**Kronecker 分解**——`U_W` 分解成 `U ∈ R^{m×m}` 与 `V ∈ R^{n×n}`（KFAC 系工作）。配合**低频更新基**（默认每 10 步），大模型上就可行了。

### 完整一层

```
G_t ← ∇f_W(W_{t-1}; B_t)                     # 梯度（m×n 矩阵）
M_t ← β₁ M_{t-1} + (1−β₁) G_t                # 一阶动量
U, V ← Eigenbasis-Estimation(G_t, M_t, U, V) # 低频更新，power iteration + QR
G̃_t ← Uᵀ G_t V;  M̃_t ← Uᵀ M_t V              # 转到旋转空间
Ṽ_t ← β₂ Ṽ_{t-1} + (1−β₂) G̃_t ⊙ G̃_t
W_t ← W_{t-1} − η_t · U ( (Ṽ_t + ε)^{-1/2} ⊙ M̃_t ) Vᵀ
```

（**事实**，Algorithm 1）

### 估计策略的两个设计轴

这是本篇给的方法学贡献（**事实**，§3.2）。**轴 1 近似来源 `S`**：`S = 2nd`（高保真）用二阶矩 `L = E[GGᵀ]`、`R = E[GᵀG]`（经验 Fisher 的代理），代价是要额外存 L、R；`S = 1st`（省内存）用一阶矩近似 `E[GGᵀ] ≈ E[G]E[G]ᵀ`，**免掉 L、R 的存储**、复用已有动量 buffer。**轴 2 旋转几何 `G`**：**bilateral**（双边，`W̃ = Uᵀ W V`，完整 Kronecker 结构）算得准；**unilateral**（单边，只在较小维度旋转）只存 L 或 R 之一，对长方形矩阵友好。

理论保证（**事实**，§3.3 Theorem 3.3）：`‖H_{U,V}‖_{(1,1)} ≤ ‖H_U‖_{(1,1)} ≤ ‖H‖_{(1,1)}`，且双边版**在所有旋转中取全局最小**——即双边旋转使基错位最小化，单边也比原始空间好。

> 这个设计空间很值得记：**SOAP**（Vyas et al. 2025）对应 `S=2nd, G=bilateral`，**GaLore 的满秩版**对应 `S=1st` 一侧（论文明确做了这个映射）。本篇把已有几个二阶优化器**统一成一个二维坐标系**，然后论证"2nd + bilateral 那一角对延迟最鲁棒"。

### Stage-aware rotation（额外的 29.2%）

由 Theorem E.6 的推论 `τ' 由早期 stage 主导`，工程上做一件很自然的事：**按每个 stage 的延迟比例分配基更新的计算预算**（**事实**，§4.4）——早期 stage 延迟大就更新基更频繁、后期更新更少，总预算不变。效果 **额外 29.2% 加速**。反向验证也做了：把频率分配**倒过来**，性能**比均匀分配还差**（附录 Fig.18）。这组正反实验很扎实。

## 为什么值得读

- **它给"异步训练的 staleness"换了一个归因**。此前的主流解释是"梯度太旧、信息过期"，缓解手段是"限制延迟（bounded staleness）""按延迟衰减学习率""加 Nesterov 动量"——全都在**梯度侧**打补丁。本篇的归因是"**优化器的坐标系选错了**"，解法在**优化器侧**。这个视角转换是本 track 里最有思想性的一处。
- **与 C-14 GBA 是同一问题的两个层次**：**GBA**（推荐，2022）把异步的**全局 batch size** 对齐到同步、用 token 控制衰减严重 stale 的梯度，是**调度/聚合层面**的解法；**Basis rotation**（LLM，2026）不动聚合、改优化器的坐标系，是**优化器层面**的解法。两者**可以叠加**（**推断**）——GBA 保证"参与聚合的梯度 batch 一致"，basis rotation 保证"即使有残余延迟也不震荡"。这是本 track 里少见的**互补**关系，而非替代。
- **与 C-08/C-10 的关系**：三篇都在治 PP，但治三种不同的病——SlimPipe 治**同步** PP 的 warm-up 气泡 + 激活显存，OctoPipe 治**同步** PP 的异构气泡，Basis rotation 治**异步** PP 的 staleness。前两者"减少气泡"，后者"接受气泡、治副作用"。这是一个清晰的三分法，值得在综述里这么组织。
- **它的理论-实验闭环非常完整**：洞察（基错位）→ 二次模型上的可视化 → 螺旋曲面的定量实验 → 收敛界（τ 与 C 乘性耦合）→ 分层延迟的有效 τ' → 算法 → 三档估计策略 → 消融（估计精度越高越鲁棒）→ 小模型到大模型的规模验证。这是本 track 里方法论最严谨的一篇。
- **对 NestPipe 的间接价值**：推荐训练也用 Adam 系优化器、也做异步（C-14 说 PS 异步是推荐训练的常态），所以"基错位放大 staleness"这个机制**理论上也适用于推荐模型**（**推断**）。但推荐模型的 loss 曲面（稀疏 embedding + 稠密 MLP）与 Transformer 差别很大，旋转是否仍然有效、块对角假设是否成立，都是开放问题（**待核实**）。
- **工程上可落地的一点**：`S=1st, G=unilateral` 这个最省内存的配置**已经优于最好的基线**（**事实**）——"资源受限也能用"，不必上完整 Fisher。

## 局限

1. **只测了语言建模**。95M–3B 的 decoder-only Transformer，OpenWebText 1B token。没有推荐模型、没有 MoE、没有多模态（**事实**），对 NestPipe 的直接适用性未验证。
2. **规模偏小**。3B 是"up to 3B"，而工业 LLM 预训练是 70B+。稀疏注意力、张量并行、专家并行与基旋转的交互完全未讨论（**推断**）。
3. **基更新有额外开销，且未与最强基线在同预算下比**。54.3% 的 GPU 小时节省是"与最竞争基线比"，而基更新（power iteration + QR + 两次投影）的成本随参数规模增长；在 3B 以上这个开销占比可能变坏（**待核实**）。
4. **块对角 + Kronecker 两个假设的组合很强**。真实 Hessian 未必满足，论文只引用了"Transformer 上经验支持"的二手证据（**事实**）；假设不成立时旋转反而可能把方向转错（**推断**）。
5. **需要与权重 stashing 配合**。实验中所有方法都用了 weight stashing（**事实**，§4.1）以保证前向/反传权重一致——所以本篇**不是**纯异步（那是 PipeDream 的 stale 模式），而是"异步调度 + 权重暂存"的组合，引用时要写清楚。
6. **没给吞吐/硬件利用率数字**。全篇指标是"迭代数""loss""GPU 小时"，**没有 MFU、没有加速比**（**待核实**）——它证明了"收敛更快"，但没直接证明"端到端训练更快"，虽然 54.3% GPU 小时间接支持了后者。
7. **早期 stage 主导 τ' 这个结论依赖"延迟 = K−k"的特定模式**，换调度（如非均匀延迟）要重新推（**推断**）。

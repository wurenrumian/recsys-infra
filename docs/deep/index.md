# 深潜专栏：教程给结论，这里给推导

读完教程，脑子里留下的多半是几句结论：随机访问打不满带宽、切分有通信代价、压缩比不等于加速比。
这些结论都对，但说不出"慢多少、贵多少、什么条件下不成立"。这个专栏补的就是这一层：把每个结论推到你拿计算器能自己复算的程度。

[教程](../guide/) 13 章每章 100–135 行，读起来快。代价是很多量只能给结论。深潜反过来：一篇只算一个量，给符号、给假设、给推导，最后用[贯穿算例](../guide/running-example)算一遍。

## 两个栏目怎么分工

| | 教程 | 深潜 |
|---|---|---|
| 回答 | 哪一层是瓶颈、有哪些解法 | 这个解法省多少、什么时候不省 |
| 密度 | 一页一个主题 | 一篇一个量 |
| 读法 | 顺序通读 | 卡住时按需查 |
| 数字 | 论文自报 + 示意算例 | 同一套算例 + 显式推导 |

两种目标放在同一页里会互相伤害：推导一多，教程就没人读；结论一少，深潜就变成论文复述。所以分成两栏。

## 每篇的固定结构

六篇写法一致。第一次读建议按这个顺序：

1. 一句话版本：这篇算什么、答案是什么，两三句白话。
2. 地图：分成几块、按什么顺序、术语各是什么意思。一张表把会用到的词先解释掉。
3. 正文各块：一块只回答一个问题。公式前面一定有白话说明，表格前面一定有读法。
4. 算例：把前面推出来的式子代进同一套参数，看落点是多少。
5. 模型在哪里不成立：这篇最该记住的部分。

如果只想知道结论，读完前两节就可以停。要自己算，再往下。

## 三条线

**线一 · 带宽从哪里漏掉（第 1 篇）**

嵌入表的开销是访存，不是计算。但"访存慢"是一个结果，不是原因。真正决定有效带宽的是在途请求数、cache line、页表与访问对齐。
算清这一层，教程第 3 章那个"30% 有效带宽"的假设才有出处。

**线二 · 放大与收敛（第 2、3 篇）**

切分把内存压力换成通信与不均衡，缓存把通信换成过期。两者做的是同一件事：把一笔开销挪到另一处，并赌那一处更便宜。
第 2 篇给切分的代数，第 3 篇给缓存与过期的代数。

**线三 · 代价函数与账本（第 4、5、6 篇）**

压缩、流水、加速比三篇都在处理"局部收益如何变成端到端收益"。工具是同一个：先写代价函数，再找交叉点，最后核对论文的口径。

## 数字约定

本专栏沿用[贯穿算例](../guide/running-example)的同一套参数（200 张表 / 400 亿行 / 64 维 fp32 / 10.2 TB / 51 ms 迭代预算），所以各篇的推导结果可以横向比较。

数字分三类，正文会标出来：

1. **论文数字**：来自论文页，标 `A-14` 这类编号，可在原页核对；
2. **推导数字**：由公式与本篇假设算出，标"推导"并给代入值；
3. **示意值**：为了让算例走完而取的量级值，标 ⚠️，不能抄进容量规划。

公式同理：集合通信的字节数、Amdahl 定律、Zipf 命中率都是标准结果，不是任何一篇论文的原创。正文会写清楚哪部分是标准结果、哪部分是论文自己的建模。

<div class="takeaway">

**这个专栏的立场**：一个系统结论如果不能写成"在某组假设下、某个量等于多少"，它就还没被理解，只是被记住了。

六篇的共同目标不是给你更多结论，而是让你在看到一个新的"X×"时，能当场判断它的前提、上限和口径。

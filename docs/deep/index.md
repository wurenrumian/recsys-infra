# 深潜专栏：教程给结论，这里给推导

[教程](../guide/)的 13 章回答"问题在哪、有哪些方案"，每章 100–135 行，读起来快。
代价是很多量只给了结论：随机访问只跑到峰值带宽的 10–50%、切分开销按 1/G 下降、压缩比不等于加速比。

这个专栏只做一件事：把那些结论推到能自己算出来的程度。每篇围绕一个可计算的量，给符号、给假设、给推导，最后用[贯穿算例](../guide/running-example)算一遍。

## 为什么另开一栏

教程需要能在半小时内读完，所以它必须压缩推导。深潜需要把推导写全，所以它必须放弃"快读"。
两种目标放在同一页里会互相伤害：推导一多，教程就没人读；结论一少，深潜就变成论文复述。

分工是：

| | 教程 | 深潜 |
|---|---|---|
| 回答 | 哪一层是瓶颈、有哪些解法 | 这个解法省多少、什么时候不省 |
| 密度 | 一页一个主题 | 一篇一个量 |
| 读法 | 顺序通读 | 卡住时按需查 |
| 数字 | 论文自报 + 示意算例 | 同一套算例 + 显式推导 |

## 三条主线

**线一 · 带宽从哪里漏掉（第 1 篇）**

嵌入表的开销是访存，不是计算。但"访存慢"是一个结果，不是原因：真正决定有效带宽的是在途请求数、cache line、页表与访问对齐。
算清这一层，第 3 章那个"30% 有效带宽"的假设才有出处。

**线二 · 放大与收敛（第 2、3 篇）**

切分把内存压力换成通信与不均衡，缓存把通信换成过期。两者都在做同一件事：把一笔开销挪到另一处，并赌那一处更便宜。
第 2 篇给切分的代数，第 3 篇给缓存与过期的代数。

**线三 · 代价函数与账本（第 4、5、6 篇）**

压缩、流水、加速比三篇都在处理"局部收益如何变成端到端收益"。共同的工具是同一个：先写代价函数，再找交叉点，最后核对论文的口径。

## 怎么读

- 先读对应教程章，再读深潜。深潜不重复教程的背景。
- 每篇的"符号与模型"要看完再读推导，否则公式里的假设会漏掉。
- 每篇末尾的 `代价与边界` 是这篇最该记住的部分：模型在哪里不成立。
- 算例块里的数字可以自己重算。算出来和我不一样时，以你的计算为准——算例是脚手架，不是答案。

## 数字约定

本专栏沿用[贯穿算例](../guide/running-example)的同一套参数（200 张表 / 400 亿行 / 64 维 fp32 / 10.2 TB / 51 ms 迭代预算），
所以各篇的推导结果可以横向比较。

数字分三类，正文会标出来：

1. **论文数字**：来自论文页，标 `A-14` 这类编号，可在原页核对；
2. **推导数字**：由公式与本篇假设算出，标"推导"并给代入值；
3. **示意值**：为了让算例走完而取的量级值，标 ⚠️，不能抄进容量规划。

公式同理：集合通信的字节数、Amdahl 定律、Zipf 命中率都是标准结果，不是任何一篇论文的原创；正文会写清楚哪部分是标准结果、哪部分是论文自己的建模。

<div class="takeaway">

**这个专栏的立场**：一个系统结论如果不能写成"在某组假设下、某个量等于多少"，它就还没被理解，只是被记住了。

六篇的共同目标不是给你更多结论，而是让你在看到一个新的"X×"时，能当场判断它的前提、上限和口径。

# 深潜 5. 气泡与 staleness：一张纸上的三个约束

<div class="deep-anchor">

**对应教程** [第 11 章](../guide/11-pipeline-parallel)给了"同步有气泡、异步有 staleness"；这里把两者写成同一组代数。

</div>

## 本篇要算的问题

第 11 章的结论是：多切 micro-batch 能降气泡但涨显存，异步 PP 能消气泡但引入 staleness。这两句话都对，但都不能直接拿来算数。

这一篇要在同一张纸上写下三个量——气泡比例、激活显存、staleness 步数——然后回答：

1. 给定级数 p 与 micro-batch 数 m，气泡到底占多少？这个公式是怎么来的？
2. 为什么"降气泡"和"省显存"是同一个约束的两面，而 1F1B 又把它拆开了一半？
3. SlimPipe 的切片为什么能"一刀切两处"？异步 PP 的 staleness 为什么随深度线性增长，而不是收敛到一个常数？

## 先给结论

- 气泡 = `(p−1)/(m+p−1)`，来自"填充 p−1 个 slot"这件事；它与激活显存不是两个约束，是同一个 m 的两种计数。
- 1F1B 把激活从 `∝ m` 改成 `∝ p`，于是"加 m 降气泡"在 1F1B 下不再涨显存。教程那条"显存-气泡两面"的链条需要加一个前提：说它时默认的是 GPipe 的排法。
- SlimPipe 的切片同时改了两个计数（`m → m·n`、`X → X/n`），所以一处操作两处收益；这是代数上的必然，不是工程上的运气。
- 异步 PP 把气泡换成 staleness，`τ ≈ p`；而吞吐 `∝ p`，两者同阶，于是净扩展性 ≈ 1。这是 `C-11` 那句 "scales linearly with pipeline depth" 的账。

## 符号与模型

| 符号 | 含义 | 取值 |
|---|---|---|
| `p` | 流水级数（stage 数） | 8 |
| `m` | micro-batch 数 | 8 / 32 / 128 |
| `n` | 序列切片数（SlimPipe） | 4 |
| `X` | 一个 microbatch 在单个 stage 上的激活显存 | ⚠️ 示意 2 GB |
| `H` | 单卡显存 | 80 GB |
| `H_m` | 单卡模型状态（参数+梯度+优化器） | ⚠️ 示意 20 GB |
| `s` | 一个 slot 的时间 | 略去，只算比例 |
| `τ` | staleness：梯度被应用前模型已更新的步数 | ≈ p |

三个要算的量：

```
气泡比例  bubble = 空闲 slot / 总 slot
激活显存  A      = 在途 microbatch 数 × 单个 microbatch 的激活
staleness τ_k    = stage k 的梯度被应用前，模型已更新的步数
```

三个公式后面都要自己推一遍。约定：只算前向，反传与之对称，比例不变。

## 推导

### GPipe：气泡 = 填充时间 / 总时间

把流水线画成格点：纵轴是 p 个 stage，横轴是时间 slot。

- 最后一个 stage 不能立刻开工，它要等前面 p−1 个 stage 各喂一次，这就是填充。
- 填充完成后，每个 stage 连续处理 m 个 microbatch。
- 所以时间线长度是 `m + (p−1)` 个 slot。

```
总位置数     = p × (m+p−1)
真正有活的位置 = p × m            （每个 stage 处理 m 个 microbatch）
空闲位置     = p(m+p−1) − p·m = p(p−1)

bubble = p(p−1) / [p(m+p−1)] = (p−1)/(m+p−1)
```

换个等价说法更容易记：每个 stage 的忙碌 slot 是 m，空闲 slot 是 p−1，比例就是 `(p−1)/(m+p−1)`。

两个端点值得记：

| m | bubble | 含义 |
|---|---|---|
| 1 | (p−1)/p | 几乎全空，流水线退化成串行 |
| m = p | (p−1)/(2p−1) ≈ 50% | 要剩一半气泡 |
| m ≫ p | ≈ (p−1)/m | 气泡与 p 成正比、与 m 成反比 |

最后一行解释了一个反直觉的事实：**加深度会同时降单卡模型状态、涨气泡**。p 从 8 到 16、m=32 时，bubble 从 7/39≈17.9% 涨到 15/47≈31.9%。PP 的深度不是越大越好。

⚠️ 这里有一个计数约定的坑：把"前向"和"反传"各算一个 slot，总 slot 翻倍但比例不变；把"一个 microbatch 的前向+反传"合算一个 slot，就得到上式。两个约定给出同一个比例，但报数时必须说清用的是哪个——否则会差 2 倍。

### 1F1B：气泡不变，激活的依赖对象换了

1F1B 的排法不改变填充时间，所以气泡公式原样保留。它改的是激活。

GPipe 必须等所有 m 个前向做完才开始反传，于是 m 个 microbatch 的激活同时活着：

```
A_GPipe = m · X
```

1F1B 填满流水线之后，每个 stage 每做一个前向就紧跟一个反传，不再攒批。为什么在途数上限是 p，而不是 m？代数上：

```
stage i 的第 j 个反传，需要 stage i+1 的第 j 个反传算出的梯度
⇒ stage i 的 B 永远比 stage i+1 的 B 晚一步
⇒ 稳态下 stage i 上"已前向、未反传"的 microbatch 数 ≤ p
```

所以：

```
A_1F1B = p · X          （与 m 无关）
```

`C-08` 把这句话说得更直接：要到最优吞吐，pipeline 在 warm-up 阶段必须累积 p 个计算单元；而现有 PP 都在 microbatch 粒度上操作，所以必须同时存 p 个 microbatch 的激活。这是经典 PP 的固有性质，不是实现缺陷。

这一步的后果是链条断裂：

```
GPipe  （链条成立）
  m_max   = ⌊(H − H_m) / X⌋
  bubble  = (p−1)/(m_max + p−1)

1F1B   （链条断开一半）
  A 与 m 无关  ⇒  显存不再限制 m
  m 的上界改由数据侧（关键 batch size）决定
  m 的下界由 interleaved 1F1B 的 m ≥ p 给出
```

**这正是 `C-08` 的问题意识**：长上下文让 X 变大、关键 batch size 让 m 变小，两头挤，气泡回到 `(p−1)/(m+p−1)` 的高位；m 小到 `< p` 时 interleaved 1F1B 干脆跑不起来。它的解法不是"再想办法加 m"，而是换掉 m 的粒度。

三种排法的差别可以压成一张表：

| 排法 | 气泡 | 激活 | 对 m 的要求 |
|---|---|---|---|
| GPipe | `(p−1)/(m+p−1)` | `m · X` | 无下界，但 m 大就爆显存 |
| 1F1B | `(p−1)/(m+p−1)` | `p · X` | 无显存上界，m 受数据侧限制 |
| interleaved 1F1B | 再除以虚拟 stage 数 v | `p · X` 量级 | **m ≥ p**，否则跑不起来 |

第三行是 `C-08` 的入口：它不是不知道 interleaving 能降气泡，是知道 interleaved 要 `m ≥ p`，而长上下文下 m 恰恰到不了 p。

### SlimPipe：把 m 乘 n、把 X 除 n

把每个 microbatch 沿序列切成 n 片，1F1B 在切片粒度上调度：

```
等效 microbatch 数  m_eq = m · n
每片激活           X_eq = X / n
```

代进上一节的两个式子：

```
bubble = (p−1)/(m_eq + p−1) = (p−1)/(m·n + p−1)
A      = p · X_eq            = p · X / n
```

看这两个式子：`n` 在一处乘在分母的 m 上，在另一处作为分子的除数。**一个操作改写两个计数，所以两处同时受益**——这是代数上的必然，不是运气。

与 `C-08` 原文的公式对照，能看出两处差异：

```
论文 §3.1:  M_acc = (1+δ) · M_a/p,   δ = 2(p−1)/n
            气泡    < (p−1)/(n·m)
本文推导:   A     = p · X/n
            bubble = (p−1)/(mn+p−1)
```

第一处是口径不同，不是矛盾：论文的 `M_acc` 是累积激活的上界，`δ` 留的是因果注意力导致的分片不均衡余量；本文的 `p·X/n` 是单卡持有量（p 片在途、每片 `X/n`）。两个数不能直接相减，只能比趋势。第二处：论文的气泡界分母没有 `+p−1`，更紧。**两者同阶、同向，可以互相校验，但不能混着引用。**

别把它写成"只会切序列"。`C-08` 还有四项配套：SwiGLU 重算 swish 而不存中间激活、Chunked KV Cache（每片一块独立张量，避免大块连续 buffer 反复重分配）、LIFO 反传（一片反传完立刻释放对应 KV）、上下文交换（因果注意力让靠后的片更贵，靠搬 Q 与部分 K/V 抹平）。切分是入口，其余是让切分不亏的配套。

而且 n 不能无限大：`C-08` 实测 n 从 p 增到 8p 时 MFU 先升（气泡减少）后降（算术强度不足），128K 上下文的拐点在 `n = 2p`。

### 异步 PP：τ ≈ p，而吞吐 ∝ p

异步 PP 让各 stage 不必相互等待。代价是梯度过期：stage k 算出的梯度，在被应用之前模型已经更新了若干步。

```
τ_k   = p − k          （k = 1..p，最前端 stage 的梯度要走完 p−1 级才被应用）
τ_max = p − 1 ≈ p
```

线性的来源很朴素：**每加一层 stage，最前端那个 stage 的梯度就要多跨一层**。所以 τ 与 p 成正比，不是收敛到常数，也不是 log p。`C-11` 的原话是 "this delay scales linearly with pipeline depth"。

把这条线接上收敛率，账就出来了。`C-11` 的收敛界里，延迟 τ 与曲率常数 C 以乘积形式出现，确定性收敛率从 `O(sqrt(1/T))` 被拖到 `O(sqrt(τ/T))`。反解"到达目标损失需要的迭代数"：

```
T_iter ∝ τ ∝ p                 （迭代数随深度线性涨）
吞吐   ∝ p                     （加 stage 就是加算力）
wall-clock ∝ T_iter / 吞吐 ∝ p/p ≈ 常数
```

**这就是 "fundamentally undermining the very scalability" 的代数形式**：加深度带来的吞吐红利，被同阶的迭代数增长抵消掉，净扩展性停在 1 附近。异步 PP 本想用"不等"换掉同步 PP 的气泡（气泡 ∝ p/m），结果换来了一个同阶的 τ。

`C-11` 的实测给这个结论配了三个数：

| 数字 | 读法 |
|---|---|
| 迭代数减少 81.7%（3B 模型，vs 最优异步基线） | 达到同样 loss 少走 81.7% 的步，不是"快 5.5 倍" |
| slowdown 1.27×（本方法，P=32 相对 P=1） | 基线是 4.24×；这组数才说明"深流水线下不退化" |
| 固定模型加 stage，收敛慢 5.81× | 这是病灶本身的量化 |

⚠️ `C-11` 全篇没有 MFU、没有端到端加速比，只有迭代数、loss、GPU 小时（同等 loss 省 54.3% GPU 小时）；并且所有方法都开了 weight stashing，所以它不是纯异步，引用时要写清。

`C-11` 还往前推了一步，值得顺手记下，因为它把"τ 是线性的"变成了一个可优化的量。分 stage 各有延迟时，有效延迟不是简单平均，而是按曲率加权的 RMS：

```
τ' = sqrt( Σ C_i² τ_i² / Σ C_i² )
```

`C_i` 是第 i 个 stage 的坐标级平滑常数（错位程度的代理）。由于早期 stage 的 `τ_i` 最大（`τ_i = p−i`），τ' 由早期 stage 主导——这直接变成一个工程动作：把基更新的计算预算按 `τ_i` 的比例分配，早期 stage 更新得更勤。实测额外 **29.2%**，而把分配倒过来比均匀分配还差。一个"τ ∝ p"的观察，最后落成了"给前几层多算点"。回头验证一句：这也说明 τ 的线性不是宿命，是可以按层买回去的。

两个相邻方案只用一句话定位，细节不展开：

- `C-09` TD-Pipe 治的是推理侧的气泡：把 prefill 与 decode 按时段拆开，气泡来自 phase 切换而非 warm-up；1.91× vs TP、2.73× vs PP，前提是 PCIe-only 集群、目标是无 SLO 的离线吞吐。⚠️ 输出长度预测的准确率未给，集中控制器是单点、未讨论容错。
- `C-10` OctoPipe 治的是训练侧的模型异构气泡：主张切分、放置、调度三者联调，摘要口径 1.09–1.49×，性能模型平均预测误差 2.12%。⚠️ 我读到的 v1 标题是 AdaPtis、v3 才叫 OctoPipe，引用前必须核对版本。

## 算例

p=8，先看气泡随 m 的变化。

<div class="example">

```
m=8    → 7/15  = 46.7%
m=32   → 7/39  = 17.9%
m=128  → 7/135 =  5.2%
m=512  → 7/519 =  1.3%
```

气泡对 m 的边际收益衰减很快：m 从 8 到 32（4×）砍掉 29 个百分点，从 128 到 512（4×）只砍 4 个点。

再看显存链。假设单卡 80 GB，模型状态占 20 GB ⚠️ 示意，剩 60 GB 给激活：

```
X = 2 GB  →  m_max = 30  →  bubble = 7/36 ≈ 19.4%
X = 4 GB  →  m_max = 15  →  bubble = 7/21 ≈ 33.3%
```

同一句"显存预算 → 最大 m → 最小气泡"，X 翻一倍，气泡几乎翻一倍。这就是长上下文难受的地方。

现在把切片插进这条链条。切 n 片后每个单位只占 `X/n`，所以同样 60 GB 能装下的单位数变成 n 倍——显存不变，气泡降：

| 排法 | 有效 microbatch | bubble | 激活显存 |
|---|---|---|---|
| GPipe，X=2 GB | 30 | 19.4% | 60 GB（贴顶） |
| SlimPipe n=4，0.5 GB/片 | 120 | 5.6% | 60 GB（贴顶） |
| SlimPipe n=16，0.125 GB/片 | 480 | 1.4% | 60 GB（贴顶） |
| 1F1B，X=2 GB | 30 | 19.4% | 16 GB |

前三行的显存完全相同（都贴 60 GB 的上限），气泡却从 19.4% 降到 1.4%——因为 `n` 改的不是"总预算"，是"每个单位占多少"这个换算率。同一笔预算，币值越小，能买的张数越多。

第四行是另一条路：1F1B 把激活与 m 脱钩，省下 44 GB 却不降气泡。这也说明"省显存"和"降气泡"在 1F1B 下已经不是同一件事了，省下来的显存得另外找地方花。

最后一行是"一刀切两处"的完整用法：先切 4 片把单位变小，再用同一笔显存换 4 倍的 m，气泡从 19.4% 压到 5.6%。

代价也要算：切 4 片后每片序列长度是原来的 1/4，原始 4096 切完只剩 1024，片间无法互相注意。n=16 正好是 p=8 时的 MFU 拐点（`n = 2p`），再细下去气泡还在降、但有算力空洞先出现。

</div>

⚠️ 全段 `X=2 GB`、`H_m=20 GB` 均为示意值，气泡公式本身不含任何假设。

把这个算例收成一句：三个约束在同一张纸上，动一个必动另一个。

```
加 m        → 气泡 ↓        激活 ↑（GPipe）/ 不变（1F1B）
加 p        → 单卡模型状态 ↓  气泡 ↑        （异步时）staleness ↑
切 n 片     → 气泡 ↓  激活 ↓  代价：序列变短、算术强度 ↓
```

所以选型问题不是"哪个方案最好"，而是"你的瓶颈允许你付哪一项"。判断顺序只有一个：先量 X 与关键 batch size——前者决定 m 的显存上界，后者决定 m 的数据上界，两个上界里小的那个才是真实的 m。

## 代价与边界

- 气泡公式是同步 PP 的标准结果，不是 `C-08` 的原创公式（教程第 11 章已声明，这里重申）。`C-08` 自己给的是 `M_acc = (1+δ)M_a/p` 与 `bubble < (p−1)/(nm)`，与本文同阶但记法不同。
- "显存与气泡是同一约束的两面"只在 GPipe 排法下严格成立。1F1B 下激活 `∝ p`，m 的上界转由数据侧决定——所以真正卡住 m 的往往不是显存，是关键 batch size 与 `m ≥ p` 这个下界。
- SlimPipe 的代价有两个。短切片损失长距离依赖（片间不能互相注意）；n 太大算术强度不足，`C-08` 的实测拐点在 `n = 2p`。
- 异步的 τ 只在"延迟 = p−k"这种同步-异步混合调度下成立。换调度（非均匀延迟、多路并行流水）要重推 `C-11` 的有效延迟式。
- `C-11` 只测了 95M–3B 的语言模型、OpenWebText 1B token。推荐模型的 loss 曲面（稀疏嵌入 + 稠密 MLP）与之差别极大，"转基"是否仍有效、块对角假设是否成立，都未验证。
- `C-09` 的"时分"只适用推理，不适用训练；`C-10` 的搜索开销与 profile 噪声敏感性未披露。
- ⚠️ 待核实：`C-08` 的 1.57× MFU 是"最高"不是平均；`C-11` 的 81.7% 含多少来自 weight stashing；`C-10` 的 v1 与 v3 实验数字是否一致。

<div class="takeaway">

**本篇结论**：气泡 = `(p−1)/(m+p−1)`，激活 = 在途 microbatch 数 × 单个激活。同步 PP 的两个代价是同一个 m 的两种计数；SlimPipe 的 n 同时改两个计数，所以一刀切两处。

异步 PP 用气泡换了 staleness，而 `τ ≈ p` 与吞吐 `∝ p` 同阶，净扩展性停在 1 附近——这是 `C-11` 那句 "linearly with pipeline depth" 真正的杀伤力。

</div>

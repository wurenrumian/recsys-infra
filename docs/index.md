## 这门课的一句话立场

推荐系统的性能问题，首要矛盾**不是算力，而是稀疏结构下的内存带宽与通信**。

50 篇论文都在这个矛盾上做交易。学会看清每笔交易的**两边**，比记住任何单个方法都有用。

## 两种读法

**按顺序读（推荐）**：从 [课程地图](/guide/) 开始，13 章是一条逐步下探的路径——先看清结构，再拆开规模，然后下沉存储，最后才换模型。

**按问题读**：如果你的系统现在卡在某个具体环节，直接跳：

| 你遇到的问题 | 从哪读 |
|---|---|
| 不知道推荐训练为什么这么慢 | [1. 推荐系统为什么和 LLM 不一样](/guide/01-why-different) |
| 显存不够，想加机器但不知道该怎么切 | [5. 切分谱系](/guide/05-sharding-taxonomy) |
| 通信是瓶颈，想压缩数据 | [6. 通信解剖](/guide/06-communication) → [9. 压缩的三条轴](/guide/09-compression) |
| 表太大，机器加到极限了 | [7. 存储层级](/guide/07-storage-hierarchy) → [8. 缓存与一致性](/guide/08-caching-consistency) |
| 想上生成式推荐，不知道系统要改什么 | [10. 从 DLRM 到生成式推荐](/guide/10-model-evolution) |

## 关于数字的诚实说明

教程里所有加速比、压缩比、参数量都来自**论文自报**，没有一个经过本仓库复现。这带来三个限制：

1. **不可横向排序** —— 不同论文的基线、数据集、硬件都不同，`8.6×` 和 `5.6×` 不能直接比大小。
2. **17 篇只有摘要** —— 这些篇目的机制细节无法完整复述，正文里标 ⚠️ 并说明哪部分不确定。
3. **算例数字是示意性的** —— 按量级取整，用来展示数量级关系，不是可直接抄进容量规划的答案。

算例数字和论文数字在文中用不同的块区分，不会混淆。

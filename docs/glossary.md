# 术语表

这门课反复出现、且容易混淆的词。按主题分组，不是字母序——同主题的词放在一起才好区分。

## 嵌入表与访问

**嵌入表（Embedding Table）**
按 ID 索引的参数矩阵。推荐模型里通常占 99% 以上的参数。`行`是某个 ID 的向量，`列`是向量的一个维度。

**gather**
按一组 ID 从嵌入表里取行的操作。系统层面的代价不在计算，在**随机访存**——第 2 章。

**scatter**
反向传播时把梯度散回对应行的操作。通常与优化器更新融合（`B-02`、`A-06`）。

**row-wise sparse 更新**
只更新本次 batch 访问到的行，不给未访问的行存优化器状态。`A-06` 靠它把 96 TB 压到 24 TB。

**working set / working parameters**
当前 batch 实际访问到的参数子集。`B-09` 的核心洞察：**working set 装得进显存，即使全表装不进**。

**去重（unique / dedup）**
819 万次查询里有大量重复 ID，先去重再 gather。省带宽，但会产生碎片化问题（见"消息碎片化"）。

## 性能指标

**MFU（Model FLOPS Utilization）**
算力利用率 = 实际浮点吞吐 / 峰值浮点吞吐。适用于**计算密集**负载。**在嵌入表上无解释力**——第 1 章。

**MBU（Model Bandwidth Utilization）**
带宽利用率 = 实际带宽 / 峰值带宽。`A-16` 提出用它替代 MFU 衡量稀疏算子。

**算术强度（Arithmetic Intensity, AI）**
FLOP / 字节。标准 roofline 的 x 轴。嵌入算子的 AI 低于 1。

**带宽强度（Bandwidth Intensity）**
`A-16` 把 roofline 的 x 轴换成的量，用于衡量"每字节数据能榨出多少带宽效率"。这是为稀疏算子设计的对齐方式。

**Amdahl 定律**
如果某项占总时间比例 p，把它优化到 0，总加速上限是 `1/(1-p)`。
实用推论：**在投入之前就能算出天花板**——第 7 章用它验证 `A-14` 的 8.6× vs 1.38×。

**扩展因子（scaling factor）**
N 卡相对基准卡数的吞吐比率。`A-03` 报 1024 卡时 79.7%（传统 MP）vs 96%（2D）。

**不均衡比（imbalance ratio）**
最慢设备工作量 / 最快设备。`A-03`：传统 MP 5.70 → 2D 并行 1.57。

**负载均衡度（degree of balance）**
`B-05` AutoShard 的指标，`min(每卡代价)/max(每卡代价)`，0~1，越大越均衡。它报 88.6%。

## 切分

**Table-wise**
按表切：不同表分给不同设备。无额外通信，但单表超大时失效。

**Row-wise**
按行（ID 维度）切。通信原语通常 ReduceScatter。适合超大表。

**Column-wise**
按嵌入维度切。通信原语 AlltoAll。**两个隐性代价**：索引要复制到所有列分片、优化器状态要按行分片各存一份。

**Data（DP）**
复制小表到所有设备。前向无通信，反向 AllReduce。

**二维稀疏并行（2D sparse parallelism）**
`A-03` 的方案：MP 外套一层 DP。G 个副本，副本内切分，副本间同步。

**3D 分片**
`B-04` EMBark 的表示法：用三元组 `(i, j, k)` = (表索引, 行分片索引, 列分片索引)。

**input-dependent 分片**
`B-13` OPER 的主张：分片方案应按**输入分布**定，而非表的静态特征。这是它与 `B-05`/`B-06` 的核心分歧。

## 一致性

**过期阈值 s（staleness bound）**
`B-02` 的参数。缓存副本允许落后的最大时钟差。s=100 时通信降 88%、精度差 0.02；s=∞ 时精度崩。

**有界过期（bounded staleness）**
允许副本不一致，但保证偏差有上界。**不是"允许过期"，而是"知道界在哪"**——第 8 章的核心区分。

**write-through vs write-back**
write-through：每次写都同步到全局表（通信贵）。
write-back：写只累加在本地，驱逐时才回写。`B-02` 的"写也允许过期"属于后者。

**gated / GA（gradient accumulation）对齐**
`C-14` GBA 的做法：把异步训练的等效全局 batch 对齐到同步，使超参可复用，切换不需重调。

**RAW 冒险（Read-After-Write）**
写之后读同一数据，必须等写完成。`A-11` 流水化预取时列出四个 RAW 依赖。

## 压缩

**同质化（homogenization）**
嵌入向量内部各维度值趋于接近的现象。`A-14` 用它作为压缩难度的度量。

**Homo Index**
`A-14` 的同质化指数，0~1。1 表示所有向量同质化为单个向量。按它把表分三类，配不同误差界。

**LSQ+**
`B-10` MPE 用作基础量化器的方案，带可学习 step size α 和 offset β 的均匀量化。

**TT 分解（Tensor-Train decomposition）**
`B-07` EL-Rec 的做法：把一整行表示为多个核矩阵的收缩结果。**"行"这个概念消失了**——这是它与量化/剪枝的本质区别。

**feature selection 是 mixed-precision 的二进制特例**
`B-12` AdaEmbed 的洞察：决定"这行要不要留"等价于"这行用 0 bit 还是 n bit"。这条把剪枝和量化统一了。

## 通信

**all-to-all**
每个设备发给每个其他设备不同数据。相比 all-reduce 的区别：模式**不规则**、负载**倾斜**、对尾延迟敏感。

**ReduceScatter**
先归约再分散。Row-wise 切分的前向通信。

**消息碎片化**
`A-15` 指出的问题：去重让消息变小但条数暴增，固定开销（握手、kernel launch）占比上升。

**scaling efficiency**
⚠️ **最容易误读的词**。`C-05` 的定义：**模型性能对计算代价的线性回归拟合斜率**。
所以 5×/21× 是"每单位算力能换回多少性能"的倍数，**不是"训练快 5 倍"**。

## 模型与流水

**DLRM**
Deep Learning Recommendation Model。Meta 提出的标准推荐模型结构：嵌入表 + 特征交互 + MLP。

**HSTU**
`C-02` 的模型。把推荐重写成 next-token 生成任务，用非 softmax 注意力，实现算力可缩放。

**气泡（bubble）**
流水并行里设备等待的空闲时间。同步 PP 的气泡比例约 `(p-1)/(m+p-1)`。

**staleness（梯度过期）**
异步训练里梯度算出与应用的间隔，期间参数已被别人更新。`C-11` 发现异步 PP 的延迟**随流水深度线性增长**。

**基错位（basis misalignment）**
`C-11` 的诊断：Hessian 的曲率基与参数更新的坐标基不一致，导致 stale 梯度被放大。"转基"可缓解。

**参数服务器（PS）**
中心化参数存储 + 异步拉推的架构。十年间被集合通信取代，`C-12` 论证其前提在 LLM 后训练里失效。

**Prefill / Decode**
推理的两个阶段：prefill 处理输入（计算密集），decode 逐 token 生成（内存带宽密集）。`C-09` 主张分时段做。

## 怎么用这张表

- **混淆"MFU"和"MBU"** → 回到[第 1 章](guide/01-why-different)，这是整门课的地基。
- **混淆"有界过期"和"异步 stale"** → 前者是**参数副本**层面的过期（第 8 章），后者是**梯度**层面的过期（第 11 章）。
- **误读 "scaling efficiency"** → 它是斜率，不是加速比。`C-05` 的 5×/21× 不能读成"快 5 倍"。
- **分不清三种压缩轴** → 回到[第 9 章](guide/09-compression)的图：行数 / 位宽 / 表示层。

如果你发现某个词在这里找不到，说明教程里用得不够多——可以直接查对应论文页。

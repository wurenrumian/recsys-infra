# 8. 缓存与一致性：允许过期多少

<div class="skeleton-anchor">

**在骨架上** 本章处理第 2、4 段的前提：能不能提前知道下一批要查什么，以及允许读到多旧的行。[回看系统骨架](00-skeleton)

</div>

## 本章要解决的问题

**读完这章你应该能回答**：缓存嵌入时"过期"的含义；一致性松弛怎么变成一个可调参数；"有界"的界该定多少。

第 7 章把表放到慢介质上，代价是延迟，缓存用来把这个代价藏起来。分布式训练里，缓存又引入了一个新问题：多个副本可能不一致。

## 先看直觉做法为什么不够

直觉上，缓存要保证一致，读到旧数据就是错的。这在数据库里成立，在训练里不成立：梯度下降对噪声有容忍度。

- 训练本身就在噪声中前进（mini-batch 采样、随机初始化）；
- 一个嵌入行用稍旧的版本更新，等于给这一步加了点噪声；
- 只要噪声有界，收敛不受实质影响。

`B-02`（HET）用数据证明了这一点。Criteo 测试 AUC：

| 过期阈值 s | WDL | DFM | DCN |
|---|---|---|---|
| s=0（严格一致） | 79.64 | 79.74 | 80.25 |
| **s=100** | **79.62** | **79.73** | **80.24** |
| s=10k | 78.84 | 78.96 | 79.76 |
| s=∞（无界） | **74.61** | **70.91** | **75.29** |

这张表的读法：s=100 与 s=0 几乎无损（差 0.02），s=10k 开始掉，s=∞ 崩掉（WDL 掉 5 个点）。

所谓"有界过期"，允许过期，同时要求知道界在哪。

## 机制拆解：怎么定义"过期"

`B-02` 的设计把一致性化简成两个时钟的比较。

每个缓存条目带两个计数器：

```
x_k^i ：第 i 个 worker 上，嵌入行 k 的副本

c_s（start clock）：上次从 server 拉取时观察到的全局时钟
c_c（local clock）：本地每次更新 +1（保证 read-my-updates）
c_g（global clock）：该行在 server 上的累计更新次数
```

有效性要求两条界同时满足：

```
c_c ≤ c_s + s        # 本地不能跑得比"拉取点"太远
c_g ≤ c_c + s        # 本地不能落后全局太远
```

第一条防止本地累积太多未同步的更新；第二条防止本地读到太旧的数据。

第二条要把 `c_c` 发给参数服务器（PS）比对，但只传时钟、不传向量，开销可以忽略。

### 读协议

```
Read(keys):
  for k in keys:
    if k not in cache:        Fetch(k)            # 从 server 拉最新
    elif not CheckValid(k):   Evict(k); Fetch(k)  # 先回写再拉
    return cache.Get(k)
```

### 写协议（这里才是创新点）

```
Write(keys, grads):
  for k in keys:
    cache.Update(k, grad)    # 直接在本地累加梯度
    c_c += 1                 # 读己所写
  Evict()                    # 只在缓存满/失效时才回写 server
```

写操作也允许过期：只累加在本地缓存条目上，直到该条目被驱逐才写回全局表。

传统 write-through 每次写都走网络，这一条直接砍掉了"每次写都要通信"。

效果：嵌入通信降低最多 **88%**（≈ 1 − 1/8.2）。

## 算例：过期阈值怎么定

<div class="example">

**问题**：`s` 该定多少？

从 `B-02` 的数据看：

```
s=0     → 通信 100%（基线）
s=100   → 通信降 88%（s 的实际效果），精度差 0.02
s=10k   → 通信降更多，精度掉 0.8 点
s=∞     → 精度崩（掉 5 点）
```

s=100 是明显的拐点：精度几乎不变，通信收益已经拿到大部分。

为自己的业务定 s，用递进式实测法：

1. 从 s=0 开始，记录基线 AUC；
2. s 取 {10, 100, 1000, 10000}，各跑一次短训练（不需完整收敛）；
3. 找到"精度仍落在噪声范围内"的最大 s；
4. 用它跑完整训练，验证。

100 这个数字是 `B-02` 在 Criteo + WDL/DFM/DCN 上测的，换一套数据分布、模型或优化器就未必成立。

⚠️ 上面的 AUC 对照表是 `B-02` 的**实测数据**（可核对），但"通信降 88%"对应的是它自己的配置；你的 s=100 未必换来同样的通信收益。

</div>

## 另一条路：根本不缓存，而是"预知"

前面是缓存 + 容忍不一致。还有一条更彻底的路，利用推荐训练的一个特殊性质。

`A-11`（ScratchPipe）的洞察：

> 嵌入表的未来访问是精确可知的，因为稀疏特征 ID 本身就在训练数据集里。

训练数据集本身就是一条预取指令流。

`A-10`（Bagpipe）把这个想法做成了 lookahead 算法：

```
定义 lookahead 值 k（往后看 k 个 batch）
输入：当前 batch、未来 k 个 batch、当前缓存状态
输出：
  1. 当前 batch 中不在缓存里的 → 乱序预取（藏延迟）
  2. 当前 batch 里未来还会用到的 → 标记缓存，TTL = 窗口内最后一次使用的迭代号
```

具体例子（`A-10` Figure 6，k=2）：

```
Batch 1：嵌入 3、9 都预取
         3 在窗口内最后出现在 Batch 2 → 缓存，TTL=2
Batch 2：3 命中 → 不预取，TTL 更新为 3
         4 未命中 → 预取
Batch 3：预取 6，缓存，TTL=4
         3 在窗口内已无未来出现 → Batch 3 后驱逐
Batch 4：预取 1；6 无 TTL 更新 → 本 batch 后驱逐
```

效果：**最高 5.6× 端到端加速**（vs 四个基线），嵌入访问开销削减最高 **92%**。

### 预知路线的代价：数据冒险

流水化会引入数据冒险（RAW，Read-After-Write）。`A-11` 逐条列出了四个：

| 编号 | 依赖 | 含义 |
|---|---|---|
| RAW-1 | 参数更新 (W) → 前向 (R) | 更新的值要给前向用 |
| RAW-2 | 参数更新 (W) → 收集受害者 (R) | 更新的值可能被选为受害者读出去 |
| RAW-3 | 插入 (W) → 收集受害者 (R) | 新填入的值可能被当受害者读出去 |
| RAW-4 | 插入 (W) → 收集 (R)，发生在 CPU 表上 | 写回的驱逐值 vs 读未命中值 |

`A-11` 用 6 段流水加 Hold mask 滑动窗口解决，代价是额外的显存（约 3 GB，⚠️ 该数值在论文里被剥离，量级由文字描述确认）。

## 两条路线的对照

| | 容忍不一致（`B-02`） | 预知未来（`A-10`/`A-11`） |
|---|---|---|
| 依赖的前提 | 梯度下降容忍噪声 | 离线训练（能看未来 batch） |
| 是否改变语义 | 是（允许有界过期） | 否（严格一致） |
| 适用场景 | 在线学习、流式训练 | 离线批量训练 |
| 关键参数 | 过期阈值 s | lookahead 窗口 k |
| 主要成本 | 精度风险 | 显存 + 流水调度复杂度 |

第三行是两条路线的根本区别。`A-11` 的效果更好（5.1× 平均，最高 6.6×），但它只适用于离线训练：在线学习时"未来 batch"还不存在。

## 代价与边界

- 预知路线在在线学习上失效，这是最大的边界。`A-10`/`A-11` 的所有收益都建立在"训练数据已固定"上。
- 缓存会漂移。`A-10` 报告静态缓存在 Avazu 上从 day1 的 91% 命中率掉到 day9 的 82%，静态缓存策略需要定期更新，否则命中率衰减。
- s 的边界是经验值。`B-02` 的 s=100 只在它的设定下有效。而且"几乎无损"只是短期训练的观察，论文没给长期数据。
- 过期与异步是两件事。`C-11`/`C-14` 讨论的异步 stale 在梯度层面，这里讨论的是参数副本层面。两者可以叠加，但机制不同。

<div class="takeaway">

**本章结论**：训练场景下，可以把缓存副本的"过期"当成一个可调参数来处理。

两条路线：
- 容忍有界过期（`B-02`）：把 s 定在精度仍落在噪声内的最大值。s=100 时通信降 88%，精度差 0.02。
- 预知未来访问（`A-10`/`A-11`）：离线训练时精确知道未来要查什么，可以做到严格一致 + 最高 6.6×，但只适用于离线。

</div>

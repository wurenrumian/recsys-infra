# 11. 流水并行与气泡

## 本章要解决的问题

**读完这章你应该能回答**：流水并行的"气泡"是什么？为什么同步流水有气泡、异步流水有 staleness，两者能不能兼得？

第 10 章说模型变稠密后计算墙成为瓶颈。稠密模型的标准解法是**切层**（流水并行，PP）。这章讲 PP 的两个固有代价和目前的应对。

## 先看直觉做法为什么不够

直觉：**层切到不同 GPU 上，像工厂流水线一样依次处理**。

问题是工厂流水线有**启动和排空时间**：第一个 batch 要依次流过所有工位才能出结果，最后一个工位在等待期间是空闲的。这段空闲就是**气泡（bubble）**。

同步 PP 的气泡比例大概是 `(p-1)/(m+p-1)`（p 是流水级数，m 是 micro-batch 数）。级数越多，气泡越大。

### 两条直觉的路，各有代价

| 方案 | 做法 | 代价 |
|---|---|---|
| **多切 micro-batch** | m 增大，气泡比例下降 | 显存涨（要存更多激活） |
| **异步 PP** | 各 stage 不等，各自更新 | **staleness**（梯度过期） |

异步 PP 看起来很美：硬件利用率大幅上升。但 `C-11` 发现了一个被忽略的**病理**。

## 机制拆解：异步 PP 的隐藏问题

`C-11`（Basis Rotation）的核心发现（摘要原文）：

> this delay scales linearly with pipeline depth, fundamentally undermining the very scalability that the method originally intends to provide

翻译：**梯度过期的延迟随流水深度线性增长，反而抵消了异步本来想拿的扩展性。**

这很讽刺：异步 PP 是为了解决"深度增加导致气泡增大"，结果深度增加又让它自己的问题（staleness）线性恶化。

### 病根：Hessian 基与坐标基错位

`C-11` 的诊断是：**stale 梯度之所以害人，是因为 Hessian 基与坐标基错位**。

用一句话解释（我的理解，⚠️ 论文正文细节待核实）：

- 参数更新是在"坐标基"（每个参数单独一个方向）上的；
- 但 loss 的曲率结构（Hessian）在另一组基上更"对角线"；
- 当梯度过期时，它指向的是**旧曲率下的方向**，在错位的基上被放大；
- 转个基（basis rotation）让两者对齐，stale 的放大效应就减弱。

效果：**81.7%**（⚠️ 具体指标含义需查原文，论文页标注为正文数据）。

### 六条应对路径的横向对比

`C-08`/`C-09`/`C-10`/`C-11`/`C-12`/`C-14` 各自从不同角度处理这个问题：

| 方案 | 思路 | 关键数字 |
|---|---|---|
| `C-08` SlimPipe | 把每个 microbatch 切成 n 片序列，激活显存和气泡**同时除以 n** | （显存与气泡双降） |
| `C-09` TD-Pipe | **时分**：prefill 和 decode 分时段做，不混在一批 | 气泡消失 |
| `C-10` OctoPipe | 异构模型的气泡要**切分、放置、调度三者联调** | （不能只调一样） |
| `C-11` Basis Rotation | 转基，减小 stale 放大 | 81.7% |
| `C-12` ODC | 换通信原语（P2P 拉推），回到 PS 的宽容 | （变长序列下） |
| `C-14` GBA | 把异步的全局 batch 对齐到同步，**不调超参来回切** | （免调参） |

## 三个值得单独理解的方案

### C-08 SlimPipe：把"除以 n"做到两处

它的思路最简洁：**把每个 microbatch 沿序列维度切成 n 片**。

为什么同时解决两件事？

```
激活显存：每片只存 1/n 的激活 → 显存 ÷ n
气泡：microbatch 数变成 m×n → 气泡比例 (p-1)/(m×n+p-1) ↓
```

**一个操作，两个收益。** 这是为什么它被判「必读」——这种"一刀切两处"的设计很少见。

### C-12 ODC：重新审视参数服务器

这篇是**反例**，非常值得读。

背景：数据并行（DP）近十年从 PS 转向集合通信（collective），理由很硬：**在负载均衡的前提下，集合通信更简单、更高效**。ring all-reduce / Horovod 把这套优势做实了。

`C-12` 的论证链：

```
"均衡"这个前提在 LLM 后训练里已不成立
  ↓（变长序列导致高方差）
前提失效
  ↓
结论要重审
  ↓
回到 P2P 拉推，重获 PS 对不均衡的容忍
```

原话（摘要）：

> the balanced workload assumption no longer holds in LLM post-training due to the high variance in sequence lengths

**这个论证方法本身比结论更值钱**：它示范了怎么"回到第一性原理重审已死方案"。

⚠️ 注意 C-12 是**反例**，不是主线。它主张回到 PS，而 C-11 在 PP 里治 stale——两者治的不是同一层的 staleness（第 12 章的读法会讲怎么区分）。

### C-14 GBA：把"切换"变成不需要调参

异步训练有个实际问题：**超参要重新调**。同步和异步的最优学习率、batch 配置都不同，切换模式要重新 sweep。

`C-14` 的做法：**把异步训练的全局 batch 对齐到同步**。这样两种模式的等效 batch 一致，超参可以直接复用。

价值：让"sync/async 切换"从"工程决策 + 调参成本"变成"一个运行时开关"。

## 算例：气泡到底占多少

<div class="example">

**设定**：8 级流水（p=8），micro-batch 数 m。

**同步 PP 的气泡比例**：

```
bubble = (p-1) / (m + p-1)

m=8:   bubble = 7/15 ≈ 47%
m=32:  bubble = 7/39 ≈ 18%
m=128: bubble = 7/135 ≈ 5%
```

**用 C-08 的切分策略**（m×n，n=4）：

```
m=8, n=4 → 等效 m=32 → bubble ≈ 18%
```

**代价**：切 4 片序列，每片的序列长度变成原来的 1/4。如果原始序列长度是 4096，切完只剩 1024——**可能损失长距离依赖**。

⚠️ 上面的气泡公式 `(p-1)/(m+p-1)` 是流水并行的标准结果，**不是 `C-08` 的原文公式**。`C-08` 还涉及激活重算等机制，这里只用标准公式示范数量级。

</div>

⚠️ 上面的气泡公式是流水并行的标准结果，不是 `C-08` 的原文公式。`C-08` 的实际做法更细（还涉及激活重算等），我只用标准公式示范"数量级"。

**关键推论**：气泡问题可以通过加 m 缓解，但**m 受显存限制**。所以「显存」和「气泡」是同一个约束的两面——这也正是 `C-08` 一刀切两处的巧妙之处。

## 代价与边界

- **异步 PP 的 staleness 必须量化**。`C-11` 的价值就在于指出"延迟随深度线性增长"这个被忽略的性质。如果你的 PP 深度不大（比如 4 级），这个问题可能不明显。
- **`C-08` 的切分损失长距离依赖**。序列切 n 片，片间无法互相注意。这对长序列建模可能是致命的，需要看具体任务。
- **`C-12` 的主张有前提**。"负载均衡不再成立"是 LLM 后训练的性质（变长序列）。推荐系统的 batch 通常形状固定，这个前提可能不成立。
- **`C-09` 的"时分"要求 prefill 和 decode 可分离**。这只适用于推理，不适用于训练。

<div class="takeaway">

**本章结论**：流水并行有两个固有代价——**同步有气泡**（随级数增长）、**异步有 staleness**（`C-11` 发现它随深度线性增长，正好抵消异步的收益）。

应对思路分三类：
1. **一个操作解决两个问题**（`C-08` 切序列 → 显存和气泡同除 n）；
2. **消解前提**（`C-12` 指出"负载均衡"失效，重审 PS）；
3. **消除调参成本**（`C-14` 对齐全局 batch，让切换免费）。

</div>
